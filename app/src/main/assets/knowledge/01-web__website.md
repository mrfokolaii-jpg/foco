# طراحی و ساخت سایت

## مسیر درست یادگیری (به ترتیب)
1. HTML — ساختار صفحه: `html`, `head`, `body`, `h1..h6`, `p`, `a`, `img`, `form`
2. CSS — ظاهر: انتخابگرها، flexbox، grid، رنگ، فونت، فاصله‌ها
3. CSS واکنش‌گرا — موبایل اول. سه نقطهٔ شکست کافی است: ۴۸۰، ۷۶۸، ۱۰۲۴ پیکسل
4. جاوااسکریپت — تعامل: متغیر، تابع، شرط، حلقه، رویداد، fetch برای API
5. Git — نگه‌داشتن تاریخچهٔ تغییرات
6. یک فریم‌ورک — Next.js (ری‌اکت) یا Astro یا Nuxt
7. انتشار روی اینترنت — Vercel، Netlify یا Cloudflare Pages

## انتخاب تکنولوژی بر اساس هدف
| هدف | انتخاب درست |
|---|---|
| فروشگاه ساده، بدون برنامه‌نویسی | وردپرس + قالب |
| سایت شرکتی چندصفحه‌ای | WordPress یا Astro |
| وب‌اپ تعاملی، داشبورد | Next.js + React |
| فقط یک صفحهٔ معرفی سریع | یک فایل HTML + CSS |
| بلاگ با رشد تدریجی | Astro یا Next.js |

قاعده: ابزار ساده‌تر انتخاب کن. پیچیدگی را فقط وقتی قبول کن که لازم باشد.

## ساختار پیشنهادی یک پروژهٔ فرانت‌اند
```
مشتری/
  public/          عکس، فونت، آیکون
  src/
    components/    اجزای کوچک تکرارشدنی
    pages/ یا app/ صفحه‌ها
    styles/        استایل‌ها
    lib/            توابع کمکی و درخواست‌های شبکه
  index.html
  package.json
```

## طراحی واکنش‌گرا
- اول موبایل را طراحی کن، بعد بزرگ‌تر.
- به‌جای عرض ثابت از درصد و `max-width` استفاده کن.
- تصاویر: `width: 100%; height: auto;`
- فونت خوانا: حداقل ۱۶ پیکسل برای متن اصلی، ارتفاع خط ۱.۵ برابر.
- دکمه‌ها حداقل ۴۴ در ۴۴ پیکسل باشند تا با انگشت راحت زده شوند.

## سرعت سایت (مهم‌ترین معیارها)
| معیار | یعنی چه | راه‌حل |
|---|---|---|
| LCP | سرعت نمایش بزرگ‌ترین تصویر/متن | تصویر سبک، فشرده، بارگذاری زودهنگام |
| INP | سرعت واکنش به لمس | کم کردن کد جاوااسکریپت اولیه |
| CLS | پرش چیدمان | برای تصویر و تبلیغ ارتفاع مشخص بده |

کارهای مؤثر: فشرده‌سازی تصویر (WebP)، تنبل‌کردن بارگذاری تصاویر پایین صفحه،
کم کردن فونت‌های اضافه، کش کردن، استفاده از CDN.

## دسترس‌پذیری (چک‌لیست کوتاه)
- هر تصویر `alt` معنادار داشته باشد.
- کنتراست متن و زمینه کافی باشد.
- همهٔ کارها با کیبورد هم قابل انجام باشد.
- فرم‌ها `label` واقعی داشته باشند.
- رنگ تنها وسیلهٔ انتقال پیام نباشد.

- شروع با طراحی گرافیکی به‌جای محتوا و ساختار

- جاوااسکریپت زیاد برای کاری که با CSS می‌شد
- نادیده گرفتن موبایل تا آخر کار
