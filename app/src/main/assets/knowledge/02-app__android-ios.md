# ساخت اپلیکیشن موبایل

## انتخاب مسیر
| هدف | زبان و ابزار |
|---|---|
| فقط اندروید، کیفیت بالا | Kotlin + Jetpack Compose |
| فقط آیفون | Swift + SwiftUI |
| هر دو، تیم کوچک | Flutter (Dart) یا React Native (JS) |
| بازی | Unity یا Godot |

## معماری یک اپ اندروید تمیز
```
app/
  src/main/java/.../
    data/          مدل‌ها، پایگاه داده، شبکه
    ui/screens/    هر صفحه + ViewModel همان صفحه
    ui/theme/      رنگ، فونت، شکل‌ها
  res/             عکس، متن‌ها، تنظیمات
```
قاعدهٔ طلایی: صفحه (UI) فقط نمایش می‌دهد؛ منطق در ViewModel باشد؛ داده در لایهٔ data.

## مفاهیم کلیدی Compose
- `@Composable` تابعی است که رابط کاربری می‌سازد.
- `remember` مقدار را بین بازترسیم‌ها نگه می‌دارد.
- `mutableStateOf` وقتی عوض شود، رابط بازترسیم می‌شود.
- `LaunchedEffect` برای کارهای زمان‌بندی‌شده و درخواست شبکه.
- هرچه «بازترسیم» کمتر، اپ روان‌تر و باتری‌کم‌مصرف‌تر.

## ذخیره‌سازی داده
- تنظیمات کوچک (کلید، پرچم، عدد): `SharedPreferences` یا `DataStore`
- جدول‌های واقعی و جستجو: `Room` (روی SQLite)
- فایل و مدل بزرگ: حافظهٔ داخلی اپ (`filesDir`) — نیازی به اجازهٔ دسترسی ندارد

## شبکه
- `OkHttp` برای درخواست، `Retrofit` برای API مرتب
- همیشه حالت خطا را در نظر بگیر: بی‌اینترنتی، کندی، کد ۴۰۱/۴۲۹/۵۰۰
- پیام خطا را **از خود سرور** نشان بده، نه یک متن کلی. کاربر باید بفهمد مشکل کجاست.

## نسخه‌گذاری و امضا (از تجربهٔ همین پروژه)
- `versionCode` عددی است و با هر انتشار یکی زیاد می‌شود.
- `versionName` متنی است، مثل «2.0».
- هر نسخه‌ای که منتشر می‌کنی باید با **همان کلید امضا** ساخته شود، وگرنه روی نسخهٔ
  قبلی نصب نمی‌شود و کاربر مجبور است اول برنامه را پاک کند.
- کلید امضا را گم نکن؛ بدون آن نمی‌توانی نسخهٔ بعدی را منتشر کنی.

## اندازهٔ اپ و منابع
- کتابخانهٔ سنگین را فقط وقتی اضافه کن که واقعاً لازم است؛ هر کتابخانه اندازهٔ اپ را
  بزرگ و راه‌اندازی را کند می‌کند.
- کتابخانه‌های بومی (native) مثل موتورهای هوش مصنوعی فقط برای یک معماری
  (arm64) ساخته می‌شوند؛ روی گوشی‌های قدیمی‌تر کار نمی‌کنند.

## اشتباه‌های رایج
- انجام کار سنگین روی رشتهٔ اصلی (باعث قفل‌شدن رابط می‌شود)
- ذخیرهٔ کلید و رمز داخل خود اپ (هر کسی می‌تواند بخواند)
- نبود حالت خالی/خطا/بارگذاری در صفحه‌ها
