# ابزارها، گیت و خط فرمان

## خط فرمان لینوکس/ترماکس — پرکاربردها
```
ls -la            فهرست فایل‌ها با جزئیات
cd مسیر           رفتن به پوشه
cp -r مبدأ مقصد   کپی
mv مبدأ مقصد      جابه‌جایی یا تغییر نام
mkdir -p مسیر     ساختن پوشه (با والدهای لازم)
cat فایل          نمایش محتوا
head -50 فایل     پنجاه خط اول
tail -f فایل      دنبال کردن زندهٔ لاگ
grep -rn "متن" .  جستجوی متن در همهٔ فایل‌ها
find . -name "*.kt"   پیدا کردن فایل با الگو
df -h             فضای آزاد دیسک
du -sh پوشه       حجم یک پوشه
ps aux            فهرست پردازش‌ها
kill شناسه        بستن پردازش
top / htop        مصرف منابع زنده
```

## Git — پیشرفته‌تر
```
git log --oneline --graph --all      تاریخچهٔ شاخه‌ها
git show شناسه                        جزئیات یک ثبت
git blame فایل                        چه کسی کدام خط را نوشت
git revert شناسه                      برگرداندن یک ثبت (امن)
git reset --hard شناسه                پاک کردن تغییرات (خطرناک)
git cherry-pick شناسه                 آوردن یک ثبت از شاخهٔ دیگر
git remote -v                         آدرس مخازن
git tag v1.0.0                        برچسب نسخه
```
نکته: `revert` امن است چون تاریخچه را نگه می‌دارد؛ `reset --hard` داده را از بین می‌برد.

## کار با کلید و رمز (خیلی مهم)
- کلید API را داخل کد یا فایل مخزن **نگه ندار**.
- کلید را در متغیر محیطی یا فایل تنظیمات خارج از مخزن بگذار.
- اگر کلیدی جایی منتشر شد، فوراً باطلش کن و کلید تازه بساز.
- در آدرس گیت، توکن را داخل URL نگذار (در تاریخچه ذخیره می‌شود).

## داکر — مفاهیم پایه
- Image = قالب آماده؛ Container = نمونهٔ در حال اجرا از آن قالب.
- `docker build -t نام .` ساخت تصویر
- `docker run -p 8080:80 نام` اجرا با نگاشت پورت
- `docker ps` لیست در حال اجرا، `docker logs نام` لاگ
- وُلوم کار می‌کند: دادهٔ مهم را بیرون از کانتینر نگه دار.

## دیباگ شبکه
```
ping میزبان              آیا پاسخ می‌دهد
curl -v آدرس             نمایش جزئیات درخواست
curl -I آدرس             فقط هدر پاسخ
nslookup دامنه           بررسی DNS
ip route                 مسیرها و گیت‌وی
```
اگر «کار نمی‌کند»: اول DNS، بعد گیت‌وی، بعد فایروال، بعد خود سرویس.

## محیط کار حرفه‌ای
- ادیتور با افزونه‌های قالب‌بندی خودکار و بررسی خطا
- قالب‌بندی یکدست کد
- فایل تنظیمات ثابت برای پروژه (تا روی هر دستگاهی یکسان اجرا شود)
- نوشتن مراحل راه‌اندازی در یک فایل README

## بهینه‌سازی کار روزمره
- کارهای تکراری را در یک اسکریپت بریز.
- برای هر کار همیشه یک مسیر مشخص داشته باش.
- از محیط آزمایشی قبل از محیط اصلی استفاده کن.
